# Health App Prototype

## Project Goal

This is a 2-day React Native + Expo health app prototype.

The target is approximately 40-50% functionality.

This is a school/project prototype, NOT a production medical application.

The project will eventually be handed to another developer who will focus on visual styling.

## Existing Project

This project already contains:

* Expo setup
* React Native
* TypeScript
* Expo Router
* Initial UI
* Mock data
* Git repository

IMPORTANT:

Continue from the existing implementation.

Do not rebuild the project from scratch.

Do not delete existing working screens or components unless there is a specific reason.

Preserve existing functionality.

## Main Features

The application contains:

1. Dashboard
2. Water tracker
3. Diet tracker
4. Weight tracker
5. Sleep tracker
6. Step tracker
7. Mental wellness check
8. Health chatbot
9. Nearby health centers
10. Doctor consultation
11. User profile

## Technology

Use:

* React Native
* Expo
* TypeScript
* Expo Router
* React state/context where appropriate
* Local/mock data

Do not introduce additional frameworks or libraries unless necessary.

## Architecture

Keep screens separate.

Use reusable components where appropriate.

Keep data/state reasonably separate from presentation.

Avoid putting large amounts of unrelated logic into one file.

Avoid duplicate sources of truth.

Use descriptive names.

Prefer simple solutions.

Do not over-engineer.

## Prototype Scope

This application only needs approximately 40-50% functionality.

Use mock or simulated functionality whenever appropriate.

Examples:

* Simulated step counts are acceptable.
* Mock health centers are acceptable.
* Mock doctors are acceptable.
* Local appointment selection is acceptable.
* Rule-based chatbot responses are acceptable.
* Local state is acceptable.

Do NOT implement unless explicitly requested:

* Real medical diagnosis
* Production medical systems
* Real doctor booking infrastructure
* Real payments
* Real health sensor integration
* Complex authentication
* Complex backend infrastructure
* External health APIs
* Real-time systems

## Styling

Do not spend excessive time on visual styling.

Another developer will handle the final visual design.

Preserve the existing UI unless a task specifically asks for UI changes.

Keep functionality reasonably separated from styling.

## Development Rules

Before making significant changes:

1. Inspect the existing implementation.
2. Identify which files actually need to change.
3. Explain the intended approach briefly.

When implementing a requested feature:

* Modify only relevant files.
* Do not rewrite unrelated code.
* Do not add unrequested features.
* Do not install unnecessary dependencies.
* Reuse existing components when appropriate.
* Preserve existing navigation.
* Preserve working functionality.

After implementation:

* Run appropriate TypeScript checks.
* Check imports.
* Check navigation.
* Fix errors caused by your changes.
* Briefly summarize what changed.

## Scope Control

When multiple approaches are possible, choose the simplest reliable approach suitable for a 2-day prototype.

Do not turn prototype features into production systems.

If a feature can be demonstrated with local state or mock data, prefer that approach.

## Git

The project uses Git.

Do not reset, revert, force-push, delete branches, or discard existing work unless explicitly instructed.

Do not make commits automatically unless explicitly asked.

Before major changes, make sure the current working state can be recovered.

## Important

The user is working under a strict 2-day deadline.

Prioritize:

1. Working functionality
2. Reliability
3. Clean handoff
4. Scope control
5. Visual polish

Do not allow feature creep.
